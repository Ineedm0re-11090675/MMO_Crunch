# 2026-11-09：让死亡组件管好 Maple ASC 绑定

MapleCombat 的死亡回调已经由 `CharacterStateComponent` 接管，不过 ASC 校正还散落在 `CCharacter::BeginPlay`。这两段其实是一条生命周期：先订阅死亡事件，再等 Maple 基类完成默认查找，最后把 Manager 指到 Maple ASC。

现在角色仍按这个顺序启动，显式重绑的细节移进状态组件。这样 `CCharacter` 不再直接依赖 MapleCombat Manager 类型；以后换 Manager 的绑定方式，只需要改组件这一处。

本轮做了静态差异检查，没有运行 UE 编译或 PIE。后续验收仍看已验证过的死亡与重生流程，确认 Manager 持续从 Maple ASC 收到死亡状态。
